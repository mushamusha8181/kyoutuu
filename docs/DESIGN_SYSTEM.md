# DESIGN_SYSTEM.md

## 役割

この文書は、今後作るアプリで共通して使うデザインの正本とする。

アプリ固有の画面構成や機能仕様は書かない。
それらは各アプリの `docs/CURRENT_SPEC.md` で管理する。

## 基本思想

> リキッドグラス × フラットデザイン

基本構造はフラットデザインとする。
リキッドグラスは前面の主要要素へ控えめに使う。

主な適用候補:

- カード
- 検索欄
- ダイアログ
- 下部ナビゲーション
- 設定セクション
- アイコン背景

全面をガラス化しない。
読みにくくなるほど、ぼかし、透明度、影を増やさない。

## フォント

標準フォントは `MUSHIN / 無心` を使用する。

情報の強弱は太字の乱用ではなく、主に次で表現する。

- 文字サイズ
- 余白
- 色
- 配置

## スマホ専用・コンパクトUI

このデザインシステムはスマートフォンアプリ専用を前提とする。
大きなボタン、大きすぎる余白、大きすぎる見出しで表示領域を圧迫しない。
特に小型スマートフォンでも、主要な情報と操作が1画面に無理なく収まる密度を優先する。

基本原則は次のとおり。

> 小さく見せる。ただし押しにくくしない。

見た目のサイズと実際のタップ領域は分けて設計する。
小さなアイコンやボタンでも、主要操作のタップ領域は原則 `48dp` 以上確保する。

### 標準文字サイズ

MUSHINを使用する前提で、通常のスマートフォンUIは次を基準とする。

- 画面タイトル: `20sp`
- セクション見出し: `16sp`
- 一覧・カードタイトル: `15sp`
- 通常本文: `14sp`
- タブ・下部ナビ・補助ラベル: `12〜13sp`
- 日時・補足・メタ情報: `11〜12sp`

通常本文は原則 `14sp` を下回らせない。
文字を小さくして情報を詰め込むより、不要な余白や装飾を先に減らす。

### 標準UIサイズ

- 小アイコン: `18dp`
- 通常アイコン: `20〜22dp`
- アイコン背景・小型操作面: `36〜40dp`
- 検索欄の高さ: `44dp`
- 一覧行: `48〜52dp`
- 設定項目: `48〜52dp`
- 通常操作ボタンの見た目: `40〜44dp` 程度
- タブの見た目: `40〜44dp`
- FAB: `48〜52dp`
- 下部ナビ: `56〜60dp + Safe Area`
- ダイアログ内側余白: `16dp`
- 画面左右余白: `12〜16dp`
- 主要操作の最小タップ領域: `48dp`

表示サイズを確保するためだけに、見た目のボタン自体を `48dp` 以上へ巨大化する必要はない。
見た目はコンパクトに保ち、透明なタップ領域などを含めて操作性を確保する。

### 小型スマートフォン

画面幅 `360dp` 以下を小型スマートフォンの基準とする。

小型画面では、まず次を圧縮する。

1. 画面左右余白
2. カード内余白
3. セクション間余白
4. 装飾的な余白・装飾

目安:

- 画面左右余白: `16dp → 12dp`
- カード内余白: `16dp → 12dp`
- セクション間余白: `24dp → 16〜20dp`

主要操作のタップ領域、本文の可読性、重要情報を先に削らない。
横方向へ無理に詰め込まず、必要なら情報を縦方向へ積む。

### 圧迫を避ける禁止事項

- 通常本文を必要以上に大きくする
- 画面タイトルを常時 `22sp` 以上にする
- 主要操作をすべて `56dp` 以上の大きなボタンにする
- カードごとに `24dp` 以上の大きな内側余白を使う
- カード間隔を必要以上に広げる
- 1画面に表示できる情報量を装飾のために大きく減らす
- 小型スマホで主要操作のタップ領域を削って帳尻を合わせる

## 実装原則

- 見た目のために操作性を落とさない
- 小さいスマートフォンでも窮屈にならない密度を優先する
- 装飾より情報の読みやすさを優先する
- 同じ役割のUIはアプリ間で可能な限り同じ見た目と操作感にする
- アプリ固有の都合で共通デザインを変更する場合は、その変更をアプリ固有仕様として扱う
- 未記載の詳細値をAIが勝手に確定しない

## 更新ルール

共通デザインを変更した場合は、この文書を更新する。

各アプリ側に同内容を重複して増やさず、この文書を共通の正本として扱う。
